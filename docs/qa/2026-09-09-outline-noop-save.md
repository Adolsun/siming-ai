# 大纲提案确认冲突：复现与修复

## 隔离复现

使用临时测试数据库创建正式章纲、带“建档关联”备注的人物关联及待确认提案。模拟编辑页保存同一标题、同一人物 ID 列表和空 metadata，再确认提案。

在独立测试进程中加载 HEAD 的原始保存方法（不回退工作区代码），同一用例稳定返回 HTTP 400：`正式大纲在提案生成后已变化，请重新生成后再确认`。日志：`.build/outline-original-repro.log`。

## 修复

- 仅提交 character_ids 表示调整关联人物集合，保留仍在集合中的人物备注；显式提交 characters 时仍可修改或清空备注。
- metadata 原值为 null 且编辑页提交空对象时保留原值；非空元数据仍可正常清空。
- characters 经 API model_dump 后为字典，统一按字典读取结构化字段，修复显式备注编辑的 AttributeError。
- 没有放宽提案的大纲指纹校验；新增正式章节、显式修改备注或非空元数据等实际变化仍会阻止旧提案确认。

## 验证

修复后原复现用例确认成功，备注与空元数据保持不变；大纲与提案生成相关测试 32 项通过。日志：`.build/outline-fixed-regression.log`。手机/PC 能力清单校验通过（27 项）；未做 Android 真机验证。

此次复现与回归没有调用真实模型或操作用户数据库。
