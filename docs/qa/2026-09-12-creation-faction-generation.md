# 立项势力生成失败：实体输出契约与诊断修复

## 问题与根因

本机 3.3.16 的三个失败运行均停在 `generate_creation_artifact` 的模型输出校验，运行记录提示没有可用的 `faction` 实体，同模型结构修复也失败。对应立项 revision 未增加，既有地点保持不变。该问题发生在保存之前，与此前写入成功后回执过大的问题是两个不同的故障。

源码中的地点阶段提示只要求 `entries` 和 `relations` 数组，没有说明势力必须位于 `data.entries`，并逐条包含 `dimension: "factions"`。原校验却依靠这一字段识别目标类型，同模型结构修复也没有得到完整的目标输出契约。原运行没有保存模型原文，因此无法确认那三次返回具体缺少了哪个字段。

这类校验错误随后又被通用错误投影替换成“工具执行失败”，外层 Agent 无法获知字段路径及修正要求。Android 的独立实体集合表还将地点阶段的全部 `entries` 视为地点，缺少势力目标映射。

## 当前实现

- `entity_contract.py` 是实体集合、输出字段及地点/势力枚举的权威定义；生成提示和一次同模型结构修复使用同一个目标输出契约。
- `generation_contract.py` 在归一化及合并既有资料前验证原始生成结构。势力必须使用 `dimension: "factions"`，地点必须使用 `dimension: "geography"`；不根据名称、正文或别名猜测类型，也不自动补字段。无效结构交回同一模型修正，修正后仍无效则明确失败。
- 已知的集合、类型字段和数量错误有固定错误码与 JSON 路径，经过 Native Agent 和中央工具结果投影后仍可见。运行记录将其归类为 `invalid_model_output` 并保存诊断；供应商异常原文及生成正文不会附带到诊断中。
- Android 从 PC 导出同一实体契约，移除单独维护的集合表，按实际条目的 `dimension` 区分地点与势力。手机独立生成、校验、修复、合并和结果反馈遵循同一契约。
- 成功的实体生成沿用既有合并与一次提交路径；失败不会用旧资料填充生成结果，也不会增加 revision。

1. 后端 212 项回归通过，覆盖本次生成修复、引用与实体历史、立项工具、Agent 收尾、结果投影和手机契约。

3. 后端数据库回归验证首次输出缺少字段后，同模型修复成功新增 4 条势力，原有实体 ID 和正文保持不变，revision 只增加一次；修复失败时资料与 revision 均不变，外层模型仍能收到具体错误码和字段路径。
4. Android 立项相关 43 项测试及 `lintDebug` 通过。独立 HTTP/SSE 回归覆盖类别选择、读取地点、生成势力、同模型结构修复和最终总结；成功只持久化一次，失败不持久化，不依赖 PC 服务运行。
