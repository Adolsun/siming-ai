# 统一建档计划修复与验证

日期：2026-09-13。工作流说明见[外部 Agent 建档](../agent/external-no-api-cataloging.md)。

## 问题与修复

原流程先提取事实，再生成档案候选。实际失败记录中，前一步将临时称呼标为匿名人物，后一步读取档案并选择了已有角色的真实 ID，却仍被前一步的判断阻止。重试重复携带上下文，也无法改变冻结的身份结论。字段类型和枚举错误是另一个独立问题，不能仅靠合并步骤解决。

现在由同一 Agent 读取完整正文和按需选择的真实档案，提交一份包含明确人物/设定 ID、场景与变更的章节计划。API 使用原生工具调用；CLI/MCP 使用同一工具注册表和字段 Schema。移除了事实提交工具、旧阶段提示词、JSONL 解析及旧上下文构建器。历史事实仍保留为审计资料，不再作为当前身份判断的否决条件。

结构错误将字段路径、约束和错误对象返回同一模型，保留已接受候选，只修正失败对象；通过 `finalize=true` 显式检查完整性。未经作者确认的旧候选可以明确撤回；作者编辑和确认的候选禁止模型覆盖。失败页默认操作为“保留候选并修正”，完整重试明确标为“重新生成当前章”。

正式摘要、人物、设定、关系、大纲、应用日志和资料对账在同一个章节事务中写入。任一写入失败，全章回滚。另修复了 FTS5 能力探测提前提交外层事务的问题。大纲和父节点不再通过标题或章节数字选择；跨作品、跨章和错误类型的 ID 在暂存前被拒绝。

数据库迁移 `300a37_cataloging_plan` 暂停未完成的旧检查点，保留历史记录和作者编辑，等待模型生成符合现行契约的统一计划。迁移兼容缺少建档状态列的早期数据库。

## 验证结果

- 后端全量：2816 通过、5 跳过。覆盖 API 原生工具循环、CLI/MCP 无内部 API 的逐章建档、并发控制、暂停/恢复、断线重连、作者确认、来源版本校验、迁移、幂等和事务回滚。
- Android：325 项单元测试通过，`compileDebugKotlin` 通过。移动端共享提示词资产已重新生成，PC/手机契约一致性检查通过；服务流程不依赖 PC 界面。
- 前端：TypeScript/Vite 构建通过，建档控制卡 5 项测试通过；OpenAPI 生成文件与当前后端一致。
- 具体回归包括：历史匿名标签与当前真实 ID 冲突、原生枚举错误的同轮修正、同名档案按所选 ID 更新、新人物/设定及其状态/时间线依赖、错误大纲 ID、场景数显式修正、旧候选明确撤回，以及完整旧背景/物品资料保留。

验证使用隔离数据库和模型协议样例，未调用用户配置的真实模型 API，也未修改用户作品数据库。Android 未进行真机安装测试。本次一个决策阶段仍可能包含多次模型请求；实际 token 节省量和不同提供商的真实生成成功率须通过新版运行记录衡量，不能由离线测试推算。

## 复核入口

运行后端测试：`python -m pytest backend/tests -q`。前端运行 `npm run build`、`npm run api:check` 和建档控制卡测试。Android 运行 `gradlew :app:testDebugUnitTest :app:compileDebugKotlin`。

共享提示词修改后，运行 `scripts/export-cataloging-prompts.py` 和 `scripts/export-mobile-prompt-contract.py`，避免各入口收到不同版本的指令。
