## 结论

真实回合 `c6a94251-14f5-485f-92e0-fcb84aa98139` 在 21:08:45 至 21:11:41（北京时间）处理“开始写新章节”，实际模型为 `deepseek:deepseek-v4-flash`，使用 API 原生工具流程。

失败由司命自身的两道固定字节边界触发。先是 3 个查询的声明结果总量超过单批 32 KiB；随后一条包含 4 个工具调用的 assistant 消息超过 16 KiB，运行时将其归为协议错误并直接结束整个回合。最后的 `project_agent` 是这个回合失败的汇总，不是另一个写入工具异常。

## 故障版本的代码核对与证据限度

- `backend/app/services/workspace/tool_result_projection.py` 定义 32 KiB 结果批次边界和 16 KiB assistant 消息边界。前者相加的是各工具的声明上限，不是实际查询结果大小；因此把 `limit` 缩小到 2，也不会减少这项固定预估。
- 同文件的 `admit_native_assistant_transaction` 会把正文、`reasoning_content`、provider state 和完整工具调用数组一起按 UTF-8 JSON 字节计量。
- 从持久记录重建最后 4 个调用时，空正文及调用本体约 615 字节。该拒绝路径没有保存整条原始 assistant 消息，不能仅凭记录断言其余字节全部来自思考内容。使用合成的 opaque 思考字段可以确定复现同一超限，但这不是恢复了真实模型思考过程。
- `assistant_native_turn.py` 对结果批次超限返回逐调用错误并继续；对 assistant 消息超限直接抛出协议错误，不能在当前回合恢复。
- `assistant_public_projection.py` 的 `public_tool_log` 将具体错误投影为“工具名 执行失败”；最终错误也只保留笼统的协议错误文案。因此界面隐藏了这次可安全展示的原因代码、字节数和容量值。
- Android `MobileConversationContext.kt` 同样定义 16/32 KiB 边界；后续修复须同时验证 PC 与手机端，而非只调整 PC 常量。

20 条成功查询的真实结果都带有分页信息；使用当前权威模型结果投影重新投递，分页字段全部保留。日志确有相同参数的重复查询，但现有证据不足以把它们归因于分页字段被系统删除；部分多次调用本来就是正常分页。

## 现行修复

现行契约为 `native_tool_transaction_budget.v3`，不再保留固定的 16 KiB assistant / 32 KiB 结果批次准入路径。

- **绑定模型预算。** 工具执行使用当前模型请求准备阶段得到的 `RequestBudgetEnvelope`；可用量为 `request_input_limit - current_input_tokens`，已经扣除了输出预留与安全余量。模型档案优先，远程未知模型的 256,000 Token 兜底不变；没有绑定预算时明确失败，不另设静默兜底。
- **完整批次准入。** 保留完整正文、思考、provider state 和全部调用 ID。执行前一次性核算 assistant JSON、所有工具消息外壳和各调用的结果上限；结果 JSON 作为消息字符串再次编码的转义开销也计算在内。整批通过后才允许任何处理器执行；容量拒绝时不执行前半批、不截断思考或丢弃调用。这保证容量准入边界，不替代各业务工具自己的事务和幂等规则。
- **分页会减少预估。** `list_chapters` 的结果上限为 `1024 + 1536 × limit` 字节，默认/最大 10 条；`search_outline_tree` 为 `2048 + 1536 × limit`，默认/最大 10 条；`search_outline` 为 `4096 + 6144 × limit`，默认/最大 2 条。返回结果还会再次校验同一页的上限。分页信息、真实 ID 和完整标题保留；异常超长的旧数据若超过契约，明确返回错误，不偷偷截断。子树固定信息计入了根节点长标题的 JSON 转义开销。
- **准备阶段预留与执行准入分离。** 对话整理为当前开放工具的一次最大结果以及消息外壳预留空间，避免刚整理后连一次正常查询也放不下。实际调用批次仍按上述剩余模型预算判定，不把准备阶段预留当成固定批次上限。
- **有界恢复。** 如果完整 assistant 加所有对应拒绝回执仍放得下，则整批不执行，并让同一个模型根据实际预算和分页契约调整。连续第三次批次准入容量拒绝停止自动重试；中途成功准入会重置计数。完整拒绝事务也放不下时直接停止，保留此前进度。容量错误使用独立代码 `tool_transaction_over_capacity`，不伪装为工具协议不兼容。
- **可见且安全的错误。** SSE 与持久步骤显示所需安全预算、当前剩余量、是否正在调整以及下一步建议。公开数据仍采用白名单，不暴露模型思考、工具参数、凭据和原始异常；被拒绝的完整消息只保存在私有诊断记录中。

这里的安全预算是 UTF-8 字节上界与消息转义开销得到的保守 Token 预算，**不是模型实际收费的 Token 数**。原故障里的 49,152 是三个结果的声明 JSON 字节总量，也不是查询实际返回了 48K Token。此次修复改变了准入依据，不能把新旧两种计量直接当作实际消耗比较。

PC 作品助手、立项助手及 Android 独立 Agent 使用相同的预算/分页/恢复规则；定时任务也接入同一模型档案与批次准入函数，并完整回传供应商状态。MCP 与 CLI 工具共享分页结果契约、参数校验和权限边界；**外部 CLI 自己管理的模型完整消息及上下文窗口由 CLI 运行时管理**，司命的 MCP 服务不能声称校验了不可见的外部整批模型请求。Windows 安装包只包含 PC 客户端，Android 源码单独验证。
