# 建档进度入口与页面缓存修复

用户点击“查看建档进度”后看不到进度，并报告系统卡顿。本轮只读检查发现：通知与任务中心链接缺少具体 job 参数；建档页挂载只加载历史，不选择链接任务，也不自动订阅进度；TabCache 缓存首次创建的 React 节点，后续路由参数和活动状态不会更新。此外，完成事件会清空已加载候选，读取详情沿用全局10分钟超时，没有持续显示的加载失败提示。

## 修复

- 建档操作通过真实 project_id/source_id 输出带 job 的链接，包括既有操作的只读序列化；不会修改历史数据库。新任务的持久化链接也包含 job。
- 工作区将 job 与页面活动状态传给建档页。页面直接请求该任务，即使它不在当前历史分页中；任务不存在时明确失败，不选择别的任务。
- 加载显示状态，15秒读取超时；可重试原任务。切换任务取消旧读取并隔离迟到响应，切走页面停止观察，回来重新加载。查看进度只读取/观察，不启动、续跑或取消建档工作。
- TabCache 保留已挂载页面的组件状态，同时更新参数。回归覆盖切换任务和未保存正文保留。
- 已完成任务使用最后完成章节载入记录，完成事件保留候选结果。
