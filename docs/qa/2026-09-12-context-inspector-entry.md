# 无作品时开启调用记录

## 问题与改动

记录策略原本按当前执行端和身份保存，立项和作品助手共用；但 UI 主要从作品页和已有回复进入，作者无法在第一轮立项前找到开关。作品入口还会筛选当前作品的记录，使已经采集的立项任务难以找到。

- PC 主界面系统菜单、作品库和系统页面顶部提供“调用记录”，不要求作品或消息；继续使用同一个查看器。
- Android 首页顶部提供同等入口，本机和 Gateway 仍明确分开。两端都能从回复或会话筛选切回“全部调用”。
- 查看器说明记录级别适用于后续立项及作品助手任务，列表显示任务类型。Android 按真实 `full_until` 区分 60 分钟与持续完整记录。
- 原“上下文治理”页面显示为“AI 参考资料”，说明它展示准备引用的资料和容量估算。任务、资料类型和缺失状态使用中文，检索维护及校验值收进详情；未知模型不再显示未经当前记录证实的 256K 容量。

未改变 API 路径、模型请求、工具权限、上下文组装、压缩算法或项目业务状态。Android 本机设置响应补齐与 Gateway 相同语义的 `full_until` 字段。

## 验证

- 后端诊断专项 17 项通过；新增回归从无项目的设置 API 开启持续记录，再通过合成立项 HTTP 请求验证实际请求正文保存、全局列表包含立项、作品筛选只影响列表。
- 前端 4 个相关测试文件 35 项通过；最后的参考资料显示调整后单独复测 5 项通过。覆盖无作品入口、持续模式、解除消息筛选、迟到详情、缺少资料的作者确认等。
- Android 诊断与立项会话两组测试共 30 项通过，`lintDebug` 和 `assembleDebug` 通过。无手机实机连接，本轮未做真机验收。
- 前端 TypeScript／构建、架构与重复率检查通过，使用打包 Python 重新完成 OpenAPI 一致性检查；后端改动测试文件 Ruff 通过。
- 使用只返回合成资料的本机预览服务，在真实 Edge 浏览器检查无作品入口、430 px 查看器布局、参考资料清单与详情。截图在本机 `output/playwright/context-entry-*.png` 与 `context-reference-*.png`。

测试未调用真实模型或修改用户业务数据库。Android 首次构建因 C 盘无剩余空间失败，依赖缓存只读复制到 D 盘后重跑通过；未删除用户文件，C 盘空间问题仍需处理。浏览器检查也使用 D 盘临时配置。定时同步保持暂停。
