# 立项实体引用失败修复与诊断

实际失败链为：按实体 ID 修改世界观条目的名字，投影同步以新名字生成了新 ID，
旧 ID 被软删除；后续角色生成仍引用旧 ID，在上下文预检阶段失败。
通用异常在工具结果安全投影中失去细节，模型无法知道需要修正哪个字段，重复提交后触发写入失败上限。
生成阶段尚未启动，不是角色模型生成了三次后保存失败。
其中第二次尝试还把实体类型写成了阶段名 `characters`，首先被类型预检拒绝；角色实体类型应为 `character`。

当前修复：

- 明确按实体 ID 的 Patch 在同一次保存中绑定原实体身份，改名保留 ID；身份冲突原子拒绝。
- 目标实体、上下文实体、对象名称和实体类型预检返回固定的安全错误代码、字段路径与修正说明。
- 安全投影保留这些已知诊断，不透传提供商异常、数据库路径或任意参数。
- 工具 Schema 直接列出可用实体类型；类型与错误说明由同一领域契约导出到 Android。
- Android 独立执行时验证引用、向模型传递明确选取的实体上下文，并保留错误代码和字段路径。
- Patch 的 JSON Pointer 操作复用同一实现，实体根删除不会错误绑定下一条实体。

未对既有资料做数据迁移或自动复活旧实体；已删除 ID 要通过工具重新读取当前有效实体。
未按自然语言猜测目标或修正类型，也没有增加 API、CLI、MCP 的备用业务路径。

回归覆盖包括改名后用原 ID 生成、失效引用在模型调用前拒绝、错误安全投影、身份冲突、
实体删除、立项会话执行、MCP 契约、手机独立生成以及原有最终回复协议修复。
详见 `backend/tests/test_creation_reference_recovery.py` 与 Android 立项 Agent 测试。
