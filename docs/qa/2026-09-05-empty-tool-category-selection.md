# 立项助手首次选择空工具类别后误报失败

错误编号：`01a60c544d3f486c99ef8e0c755f1a16`。日期：2026-09-05。状态：已修复，通过源码回归、真实 OpenCode 调用和打包后 MCP 验证；本地 Windows 测试安装包已生成，未发布 Release。

## 结论

这是司命临时 MCP 工具类别状态的处理错误。模型确实调用了 `set_tool_categories`，参数为 `{"enabled_categories":[]}`。空列表是工具契约允许的选择，表示当前回复不需要业务工具；系统却把首次选择空列表当成重复选择，不更新状态，最终误报“没有调用工具”。不能通过判断问候语关键词绕过流程，也不能取消必须先选择类别的边界校验。

## 实际调用记录

- 新的司命进程 PID 45268 于 20:46:07 启动，父进程为 Explorer（PID 12868）。只读查询得到 RedirectionTrust Flags 为 0，已不受上一次安装器路径防护限制。
- 本轮用户消息为“你好？”，开始于 20:46:44，20:47:10 被保存为失败。会话 ID 为 `7fb38497-f1cc-42af-a895-981373e5b7e3`。
- 对应 OpenCode 会话为 `ses_f8e649100ffek6JEuatPdwc8u5`，版本 1.18.4，实际模型 `opencode/big-pickle`。
- OpenCode 的工具记录包含真实调用 `siming_turn_set_tool_categories`，参数为 `{"enabled_categories":[]}`。
- 工具返回 `status=skipped`、`reason=categories_already_active`，并告诉模型“业务工具已经关闭；如无需工具，请直接回复作者”。OpenCode 将这个 MCP 结果记录为工具错误。
- 模型随后正常返回问候并询问作品方向，没有调用任何业务写入工具。
- 司命外层却抛出 `本机 CLI 没有调用临时 MCP 中唯一开放的 set_tool_categories，本轮已终止，未接受 CLI 返回的等待或完成文字`，将正常回复拦下。`launcher.log` 对应第 907 行。

## 代码原因与隔离复现

修复前，`backend/app/services/tool_category_state.py` 的 `replace_tool_categories` 在初始状态 `version=0`、`active_categories=[]` 时，仅比较新旧类别相等就返回 `skipped`。没有区分“尚未选择类别”与“模型明确选择空类别”。

`backend/app/services/novel_creation_agent.py` 的 `_run_direct_mcp_steps` 使用版本推进来确认控制工具已执行；由于首次空选择没有推进版本，它在 `observed_version == 0` 时误报没有调用。原 `_cli_mcp_system_prompt` 同样只通过类别是否为空区分初始步骤；这也会让非空类别切回空类别后继续收到强制选择的提示。

修复前，直接创建临时状态文件并调用 `replace_tool_categories(state_file, [])`，得到：

| 检查项 | 结果 |
| --- | --- |
| 调用前 version | 0 |
| 工具返回 | skipped / categories_already_active |
| 调用后 version / active_version | 0 / 0 |
| 类别选择事件 | 空 |

该复现不需要模型、API 密钥或用户数据库。临时状态目录经过路径验证后由现有清理函数删除。

## 实际修复

1. 直接更新共享状态实现：只有已有有效选择记录（`version > 0`）时，相同类别才按重复选择处理。首次空选择返回 `ok`，推进版本并记录一次事件；激活后业务工具仍为空。
2. 立项 CLI 提示词和进度依据已经确认的选择状态区分初始步骤与后续步骤。首次空选择、非空切回空后均允许完成不需要业务工具的回复。
3. 未调用控制器、非法参数、权限交集、回合终止、业务写入边界保持原校验；没有增加问候语关键词判断、备用路由或迁移状态。
4. 原生 API 和手机端本来就有独立的已选择状态，本次增加一致性回归，不修改手机端业务实现。
