# 立项助手思考协议错误修复与回归记录

日期：2026-09-05。分支：`codex/hci-usability-20260905`。基础提交：`dcf46329ed59e36e229bf782dc66068c841b2aef`，工作区有未提交改动，版本号仍为 3.3.13。

本轮修复两个实际报错及同类协议问题。没有修改用户的模型配置、密钥、作品、正文或建档数据；没有关闭思考模式，没有新增按用户自然语言猜测业务意图的分支。

## 根因与修复

| 问题 | 证据与原因 | 当前行为 |
| --- | --- | --- |
| 错误 `98be0dea722f4527bd171c749eba9d41` | 上游拒绝 thinking 模式下的 `tool_choice`；自定义提供商名称 `ds` 使用 OpenAI 兼容适配器。网关虽删除该参数，但实际重发依赖普通重试次数，立项调用 `retry=0` 时没有发送修正请求。 | 参数修正有独立的一次机会，只在尚未收到任何流事件、上游明确拒绝该字段时生效；普通网络重试仍按原预算处理。修正记录进入请求元数据及诊断日志。 |
| 错误 `124ac9bcd5ae456c8fe4b1ae33a2f2a7` | 类别选择成功、读取立项资料成功后，第三步将已消费的类别事务压成服务器回执，却把回执标为 assistant，缺少 DeepSeek 必需的原生 `reasoning_content`。最近一次读取工具的原生思考字段实际上已保存。 | 服务器回执作为独立 user 参考资料放在最新作者消息前，保留 `data_only: true`。最新作者原文仍是最后一条 user，后面仅保留待消费的原生 assistant/tool 事务。 |
| 历史失败、取消状态与 checkpoint 修复 | 服务器自己生成的状态说明也曾伪装成 assistant。 | 状态回执使用参考数据角色；checkpoint 结构修复不再插入虚构的模型回复。预算计算同步修改。 |
| 断流续传 | 用不完整文本伪造 assistant，缺少完整提供商状态；失败尝试与成功尝试的思考增量还会被串接。 | 已提交文本进入明确标记的参考数据，保留原作者消息与断点握手。工具事务只采用最终成功响应的思考字段和签名状态；不完整工具参数不对执行器开放。 |
| 无效请求反复重试与错误提示 | 同一协议错误可消耗多轮普通重试；只有字段名的粗略匹配可能把鉴权、限流误当成参数拒绝。 | 区分上游状态与司命公开的 502 包装状态，鉴权、额度、网络错误不触发参数修正；确定性无效请求及时停止。PC 立项和正文助手展示安全的协议错误说明，立项保留错误编号。 |

修改现有公共网关、ContextFrame 渲染和原生响应收集器，没有建立第二条立项或正文业务路径。Android 的独立渲染器和直接 API 续传同样调整，不依赖 PC 正在运行。手机原生工具流在输出后失败时仍直接停止，不新增工具续传路径；已有正文续传保留断点校验。

## 真实 DeepSeek 接口验证

使用当前已配置的 DeepSeek V4 Flash 凭据，经司命请求级配置接口运行；仅在进程内分别使用自定义别名和内置提供商，未改写持久配置。实际通过当前网关、适配器及 ContextFrame 向上游发送请求，没有模拟上游响应。工具数据为明确声明的虚拟协议测试资料，工具回执保存在隔离测试目录，不操作用户作品。

| 路径 | 类别选择 | 读取资料 | 压缩类别事务后的回复 | 结论 |
| --- | --- | --- | --- | --- |
| 自定义 `ds` / OpenAI 兼容适配器 | 4.08 秒；拒绝 `required` 后自动去参重发一次 | 2.55 秒；原生思考回传 | 1.88 秒；回执置于作者消息前，读取事务原生思考回传 | 通过 |
| 内置 `deepseek` / DeepSeekAdapter | 2.05 秒；按既有能力配置省略参数 | 3.27 秒；原生思考回传 | 1.73 秒；成功完成回复 | 通过 |

两条路径的第三步均为 `system → user参考回执 → user作者原文 → assistant原生调用 → tool结果`，均保留 thinking，且最终无新的工具调用。真实接口测试不等同于整篇小说生成或安装包界面验收。

前两次自定义别名探针分别因测试程序未重新封装 frame hash、未持久化压缩所需结果引用而停止；均为本地 `ValueError`，不算接口协议验证通过。修正探针并实际持久化隔离回执后重新完整执行，以上只列完整通过记录，原始失败记录保留。
