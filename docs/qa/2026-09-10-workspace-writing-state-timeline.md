# 建档完成后继续写章与聊天时间线

## 实际问题

只读检查作者数据库确认：相关章节的草稿已保存，当前正文 v1 于 2026-09-10 11:04（北京时间）完成建档，作品没有 pending 草稿，所有现存章节的 cataloging_required 均为 false。11:27 的助手却再次回复“当前仍有未保存的章节草稿”，该次运行没有持久化业务工具步骤。

模型上下文保留历史中的“草稿尚未保存”回复，但运行时此前只在客户端传入 active_chapter_draft_id 时提供该草稿信息，没有提供当前作品完整的草稿和建档阻塞状态。作者保存、后台建档完成发生在聊天之外，历史结论因此可能被误用。

界面另把对话消息和建档通知各自排序，再将全部建档通知拼接到末尾；旧通知始终挡在最新用户消息之后。通知保留范围还按任务创建时间截取，会遗漏后来恢复完成的旧任务。

## 修改

- API 和本机 CLI 在每个模型步骤重新读取数据库，使用写章工具同一组 pending 草稿、未结束作者建档任务、当前正文待建档标志查询，生成紧凑 chapter_writing_state。明确无阻塞时不再让历史提示充当当前状态。
- 重新读取会使其他请求中的作者保存、建档完成及后续正文版本变化在下一模型步骤可见。现有写入工具仍在执行处校验；不修改自然语言、不选择下一章、不绕过保存或建档约束。
- 聊天按通知实际活动时间插入已有对话；对话仍保留服务端 sequence_no 顺序，未持久化的新消息不会被旧通知挤到底部之前。通知按实际活动选取最近三项，每项任务仍只有一条通知。
- 手机共享提示词资产同步更新。导出器从权威 PromptSpec 读取版本，移除易过期的固定版本文本。
