# 建档重复执行与恢复链路回归记录

本轮针对作者安装上一版测试包后再次发生的建档失败。不是旧安装包未生效：已核对正在运行的 `D:/Siming/Siming.exe`，其 SHA256 与上一版构建产物一致。最新失败发生在北京时间 2026-09-07 21:48—21:49，第 42 章的建档任务暂停。

本轮只读备份作者数据库，在独立目录中运行真实模型。未对作者原数据库执行修复 SQL，未自动安装，未发布 Release，也未合并分支。私有小说正文、模型请求、密钥和数据库不进入本报告或公开证据文件。

## 失败原因和修复

1. **进度连接又执行了一遍任务。** 启动/重试接口已经向后台队列提交建档，API `/cataloging/{job_id}/stream` 却再次调用执行器。现场事实记录中存在两组按秒交错的抽取序列，关系名称也各不相同。新增测试在第一条模型请求尚未返回时，打开两个连接并重连，旧实现触发了 7 次请求。修复后所有后端的进度接口只读取已提交状态，内部 API 建档只能由统一后台队列执行；同一任务另有跨进程执行锁。原本位于 CLI 模块的独立观察实现已移除，统一到 `cataloging/progress.py`。
2. **摘要误带世界观字段，反馈不足。** `source_fact_titles` 被模型写进 `chapter_summary`，且写成对象。规范要求它位于世界观候选中，值为字符串数组。共享提示词、示例和错误反馈现在明确字段位置；被拒绝的包装对象也会正确显示实际候选类型。不自动挪动或删除模型字段。
3. **已保存映射与摘要/关联名称不一致时，模型反复补错对象。** 测试中世界观候选已将“001号卷”映射到精确的现有卡 ID，但摘要与章节关联仍写原称呼。原反馈只有“缺少世界观候选”。现在 API 重试和 CLI 工具结果共用 `coverage_repairs`，指出发生冲突的候选 ID、字段和模型已声明的规范标题。该反馈只依据明确的结构化映射，不从正文猜测身份，也不代替模型修改数据。
4. **格式问题可能漏掉大部分事实，却报完成。** 实际模型输出了多条末尾带逗号的对象，旧流程只采用成功逐行解析的尾部记录。本轮曾出现“1 条事实、5 条候选、完成”，经原始输出审计后明确撤回该次验收结果。现增加完整响应校验，支持对象分隔逗号、JSONL、数组、包装对象和跨行 JSON；所有记录都必须被完整解析。非法或截断片段触发原有有界重试，不能用部分事实进入候选生成；失败尝试的临时事实也不得留给第二阶段重用。已移除原先只在零事实时运行、会跳过坏片段的补救解析路径。
5. **恢复中的字段异常会绕过重试。** `chapter_link_mode=replace` 缺少完整关联数组时，合并函数抛异常；恢复分支再次触发同一异常，导致首次候选请求后就失败。权威候选存储函数现在把这类模型结构错误返回为可修复的拒绝结果，列出缺少或不是数组的字段，并保留已有候选。

进度观察与执行分开后，同步检查了显式恢复操作：切换自动模式、确认写入和跳过当前章由各自命令启动后续工作，不依赖打开进度连接。界面使用数据库事实 ID 更新列表，重连不会重复展示同一事实；替换连接或离开页面会取消旧连接，旧连接迟到的事件不能覆盖新状态。“继续运行”按钮改为“查看实时进度”，区分观察与启动。

## 测试方法

- 单元与集成回归使用文件型 SQLite、多会话、实际 FastAPI/ASGI 流式响应及生产后台队列；仅模型服务用受控输出替换。覆盖两个观察者、断线重连、重复排队、任务结束后重新连接、暂停/取消/等待确认、手动转自动和显式跳过。
- 真实模型回归使用本机已配置的 `deepseek:deepseek-v4-flash` 和失败章节的只读副本。在独立的本机 HTTP 服务上调用公开重试接口，保留真实后台排队，连接两个 HTTP 观察者，断开并重连一个，再尝试由第二进程领取同一任务。不是把排队替换成一次内联执行。
- 另对本轮已发现的名称映射失败保留 18 条事实和 19 条候选，复制成恢复检查点，再经后台队列和 HTTP 观察者运行真实模型。检查点的暂停状态由测试夹具在私有副本中设置，不声称是作者点击“完整重试”的结果。
- 对比实际模型输出中的完整事实数与数据库来源事实数；检查候选覆盖、候选应用状态、章级大纲归属和子节点、正文不变，以及重复应用同一批候选后正式表不变。

## 本轮修正的测试盲点

上一份《建档校验与恢复测试记录》里的真实章节按钮测试调用了重试接口，但把后台排队替换为内联阶段执行，因此没有覆盖“后台任务 + 界面订阅进度”的并发组合。该测试不足以证明真实界面不会重复建档，本轮已补足。

不以重试多次偶然成功作为通过依据：保留本轮发现新缺陷的失败副本、原始模型输出和日志；对每种新缺陷补充可重复的回归。尤其不把上述少事实的“完成”当成数据可靠的结果。

- 手机在线建档使用同一 HTTP 接口和后端契约，本轮覆盖了同时在线观察的行为；没有用真实手机点击来代替说明。Android 独立/离线建档仍是既有明确能力缺口，本轮没有把它说成已实现。
- CLI 候选存储、提示词、观察器和模式切换纳入回归；本轮未新增一次真实 CLI 模型建档测试。
