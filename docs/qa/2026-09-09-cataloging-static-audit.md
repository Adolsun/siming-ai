## 已确认并修复

| 问题 | 原因与影响 | 当前处理 |
| --- | --- | --- |
| 长章节信息丢失 | 内联正文按 7,000/24,000 字符截断；候选阶段事实按 12,000 字符截断，甚至截断 JSON | 传入完整正文与完整事实；CLI 保留完整文件读取路径。删除较弱的本地模型专用事实提示词，使用共享契约 |
| 本地模型输出容易截断 | 本地阶段限额为 1,600/4,096 tokens，与完整建档输出要求不匹配 | 与同阶段 API 限额一致；不再通过限制事实数量缩减任务。完整输入会增加单次输入量，不能承诺每次请求都更便宜 |
| 半份事实被当成检查点 | 流尚未结束便逐条提交，取消后会复用不完整事实 | 完整响应解析成功后，在一个事务中保存事实及阶段状态；中断时不形成可复用的半份事实 |
| 重试重复犯同一错误 | 第一阶段重试未提供具体解析错误；第二阶段完整响应恢复后可能仍传递逐行解析噪声 | 重试携带实际错误；完整响应恢复使用实际候选校验结果，达到最低覆盖也不能吞掉无效候选 |
| 无效请求反复消耗调用 | 上游拒绝请求后，建档外层仍重复调用 | 复用上游错误解析，对认证、权限、请求过大、参数/协议拒绝停止同请求重试；408/409/425/429 不在此直接拒绝范围 |
| 暂停、取消没有停止在途请求 | 仅修改数据库状态；迟到异常还能覆盖作者控制状态 | 控制事务成功提交后停止进程/任务；回滚不停止；处理流和写入前核验控制状态；迟到异常不能覆盖暂停、取消或完成状态 |
| 恢复时丢失新 worker | 旧取消任务仍在注册表，恢复复用它；旧任务退出时可能删掉替代任务 | 恢复等待旧任务退出后启动新任务；清理注册表时核验任务身份 |
| CLI 已保存结果却显示失败 | 进程退出码或异常覆盖数据库已提交阶段 | 已提交检查点优先；候选已保存时正确进入人工确认，完成结果不被迟到退出错误推翻 |
| CLI 重试预算串阶段 | 仅按章节计数，事实阶段已用重试次数影响候选阶段 | 按章节与阶段分别计数，阶段成功清除对应计数 |
| 旧版本任务继续消耗模型调用 | 重试、模型启动和应用未统一核对章节版本及归属 | 在重试、内部模型/托管 CLI 启动、应用前校验真实章节归属和记录版本；版本已变化时要求为当前版本重新建档；REST 返回校验错误而非内部错误 |
| 终态任务被普通控制重新打开 | 暂停、继续、取消无状态边界 | 普通控制不能重新打开已完成/已取消任务；保留作者明确发起的“重跑第二阶段”操作 |
| 提交前启动 worker | 外层工作单元延迟提交时，后台任务可能先于事务运行 | 延迟提交范围内，启动也延迟到外层提交后；回滚清除启动请求，保存点提交不会提前启动 |
| 候选增量合并带入过期字段 | 仅校验新增量，没有校验与旧候选合并后的完整数据 | 合并后重新校验人物档案/状态和覆盖清单；拒绝模型覆盖作者已编辑/批准候选 |
| 人物简称到写入时才失败 | 前一轮真实样本中的人物简称没有绑定真实人物 ID | 候选阶段提前校验并返回可选真实 ID；模型自行选择；应用复用已校验人物，不再重新按简称查找 |
| 部分成功后重试丢失审计或脏写 | 单条失败可能留下部分变更；重试删除已应用候选与日志 | 单条候选使用保存点；失败回滚该条。已有正式写入时保留已应用候选、日志和源事实，仅重建待修复部分 |

## 验证边界

- 上述测试验证确定性流程与恢复，不证明所有真实模型都会正确抽取业务内容，也不能消除供应商断网、额度耗尽或模型上下文上限。不会用虚构事实或静默跳过章节把失败伪装成成功。
- 本轮控制中断覆盖当前服务进程持有的 worker；没有声称完成跨进程 CLI 故障切换或真实外部 CLI 提供商的端到端验证。
- Android 连接 Gateway 使用同一权威建档接口；Android 独立模式的完整章节建档仍是现有能力清单中明确记录的缺口，本轮没有实现该独立运行能力，也没有做手机真机验收。
- 不把未复现的所有别名、实体解析或全项目并发问题概括为已解决；本轮修复不新增自然语言意图匹配器。
