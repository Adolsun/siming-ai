# 调用与上下文查看器

首期功能位于 `codex/context-inspector`，当前基于 3.3.17；上下文查看器随本分支的本地测试包提供，尚未发布。

## 使用

- PC：主界面左侧“系统” → “调用记录”，或作品库顶部的“调用记录”，无需作品、立项会话或已有回复即可打开并设置记录级别。项目助手或立项助手已保存回复时间旁的“查看本轮调用”会筛选该回复；作品的“连续性与档案” → “AI 参考资料” → “查看调用记录”会筛选该作品。打开后标题均为“调用与上下文”，点击“全部调用”可解除列表筛选。
- Android：首页顶部“调用记录”无需先创建作品，项目助手消息、立项会话和立项回复旁也有入口。“此手机”读取本机记录；选择“Gateway”才读取该设备在 Gateway 上的授权记录。可点击“全部调用”解除会话或回复筛选。
- 默认仅记录摘要。需要检查完整交互时，先选“完整记录 60 分钟”或“持续完整记录”，再发起新任务。到期后新任务回到摘要，已经开始的任务保持当时级别。
- 选择任务、步骤，再选择实际 API 请求、提供商返回、工具参数、执行器回执或送回模型的结果。PC 优先选中失败任务和失败步骤。
- “导出”保存当前已结束任务的 ZIP；“清空”仅删除本执行端、当前身份的已结束诊断记录。诊断操作不会改动会话历史、作品、草稿或恢复检查点。

记录级别按执行端和当前身份保存，不绑定作品或当前页面。先开启“持续完整记录”，再发起新书立项，即可记录后续立项调用；切换页面不会关闭它。手机独立模式与 Gateway 分别设置。每个任务开始时确定记录级别，持续模式保留到手动更改，但历史记录仍受保留时间和空间限额约束。

“AI 参考资料”展示写作等任务准备引用的作品资料、缺失项和容量估算；实际 API 请求、响应和工具交互在“调用记录”中查看。容量中的 token 是模型的文本长度计量单位，资料估算不等于提供商实报消耗。开启记录不改变模型收到的上下文，也不启用新的压缩算法。

完整记录会包含正文、系统提示词、历史和工具结果。记录默认留在执行端私有诊断库，不自动上传、不同步到作品、不进入 Android 备份。凭据键值和采集时已知的密钥会在持久化前脱敏，导出再使用同一脱敏规则。

## 能看到什么

| 内容 | 语义 |
| --- | --- |
| ContextFrame / 应用请求 | 当时准备的上下文与应用层调用输入，不用当前数据库重新拼接历史 |
| 实际 API 请求 | 现有 HTTP 客户端真实派发的脱敏 JSON，包括最终路径、messages、tools 与参数 |
| 提供商返回 | 已观察到的 JSON 或按顺序保存的 SSE 数据帧；与适配后输出分开 |
| 模型步骤 / 请求尝试 | SDK 重试和重定向各自保留物理请求；工具内部的生成请求保持父子关联 |
| 工具调用 | 原始参数、前置拒绝、执行器回执、模型可见结果及 native call ID（边界提供时） |
| checkpoint | 现有压缩生成、验证/发布步骤与当时 ContextFrame，未引入新压缩算法 |
| 用量 | 仅显示观察到的提供商实报字段；未返回、未采到的值为未知，不补零、不推测费用 |
| CLI | 司命传给进程的输入和 CLI 暴露的输出；不声称看到外部进程内部的请求或压缩 |

普通正文中的 DSML 字样只是模型输出，查看器不会把它转换成可执行工具。`reasoning_content` 仅为提供商实际返回的字段，隐藏的内部思考无法查看。

“已记录”指这一观察边界的脱敏副本；不代表任务成功或所有层都有正文。“未记录正文”“部分记录”“采集中断”与业务的完成、失败、取消分别表达。调用方可能在结束标记后主动关流；此时仅保留已经安全解析的部分，并明确标注读取未到 EOF。

## 限额与读取

- 默认保留 7 天；PC/Gateway 总预算 256 MiB、Android 128 MiB。为写入日志保留空间，诊断数据库页分别限制在 128 / 64 MiB，并提前清理已结束任务。
- 请求或响应的诊断副本最多 16 MiB。应用结构还会做深度、序列化与保守内存预算检查；部分内容可能提前停止采集，具体原因随记录保存。
- 传输缓冲、写入队列分别限制在 32 MiB。队列或磁盘不足时丢弃诊断内容并显示缺失，实际模型数据继续传递。
- Android 对解压与脱敏的并发占用设限，繁忙时正文标记 `capture_busy`。不存在为采集等待磁盘或串行执行模型的业务路径。
- 列表和事件分页；正文每次读取最多 65,536 个 Unicode 码点，由后端返回下一段位置。导出只处理当前选择的任务，单个内容有界，不一次读取所有任务。
- 一份 trace 内按递增 sequence 排列，不依赖墙钟；不同任务通过显式 ID 关联。诊断事件不会插进聊天消息列表。

## 当前边界

- 开启完整记录只能影响后续任务，不能恢复已经过去的原始请求。
- CLI 工作进程和外部 MCP 未暴露的内部调用不可见；外部建档 worker 的启动记录明确标注这一边界。
- 摘要的用量观察采用有界解析；很大的非流式响应、无法安全解析的内容或提供商未给出的字段保留未知。完整响应中实际存在的 usage 仍可直接查看。
- 第一期提供原始分层数据与统计字段，尚无自动 token 归因图、语义压缩优化、一键重放、费用计算或 OTLP 自动上传。ZIP 暂无内置 Phoenix 导入器。
- Android 的本机数据库和查看器不依赖 PC/Gateway；本轮环境没有连接实机，安装体验和移动设备性能仍需实机验收。

## 验证证据

回归均使用临时数据库、合成内容和 HTTP mock，没有调用真实模型或消耗模型 token。

- 后端按模块隔离运行 241 个测试模块；修复首轮发现的问题后，相关 62 项回归通过，最终诊断专项 16 项通过。覆盖调用契约、设备/资源归属、连续重定向、SDK 429 重试、流中断、取消、采集失效、空间回收、应用重启及 Unicode 分页。
- 前端完整运行 58 个测试文件、320 项用例；首轮发现一处旧按钮选择器歧义，修正后相关 29 项通过，最终查看器专项 4 项通过。覆盖前置失败、未知正文、迟到请求不串消息；检查真实 Edge 浏览器的桌面和 430 px 窗口布局。
- Android 全部 308 项单元测试、Lint 与 APK 构建通过。覆盖直连流式/gzip、真实发送地址和鉴权保持一致、并发协程/取消、采集繁忙时业务继续、共享脱敏样例、ZIP 内容与哈希。Room 编译验证本机按关联 ID 过滤后分页的查询；数据库与 UI 的实机运行仍待验收。
- 架构、提示词、API 类型、移动端能力契约、前端构建和 Windows 安装包构建通过。打包程序通过 MCP 冒烟检查（153 个工具、隔离写入与 JSON Patch、历史版本标记归一化），安装包 SHA-256 校验通过。

Windows 合成基准（40 次 / 模式，每次 256 KiB JSON 响应，HTTP MockTransport，落盘等待位于计时外）：

| 模式 | P50 | P95 | tracemalloc 峰值 |
| --- | --- | --- | --- |
| 关闭 | 0.518 ms | 0.726 ms | 0.14 MiB |
| 摘要 | 1.495 ms | 1.933 ms | 0.19 MiB |
| 完整 | 1.531 ms | 2.000 ms | 1.35 MiB |

三种模式均无队列丢弃或写入失败。本机该基准的验收阈值为 P95 额外耗时低于 25 ms；结果不代表真实提供商网络耗时、完整首字延迟或 Android 实机性能，也不是整个应用 RSS。
