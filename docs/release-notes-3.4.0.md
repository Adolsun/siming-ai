# 司命 3.4.0

3.4.0 内置调用与上下文查看器，改进建档计划、候选修正与工具调用恢复，并减少自动数据库备份的空间占用。

**本版本主要为后续上下文优化做准备。接下来的上下文组织、工具描述精简、压缩机制与效果验证，主要以 DeepSeek API 的 `deepseek-flash` 为优化和测试基准。** 本次先提供可观察的请求与响应记录，并完善执行边界；尚未据此完成新的上下文压缩策略，也未测得统一的 token 节省比例。

## 调用与上下文查看器

- PC 可从主界面“系统 → 调用记录”打开，作品库、立项助手和项目助手也提供入口。无需先创建作品，即可开启记录并检查后续立项交互。
- Android 提供本机调用记录入口，独立模式无需 PC 客户端运行；Gateway 记录按对应执行端和授权身份查看。
- 支持查看实际发送的请求、可用工具契约、模型返回、工具参数与执行结果，并区分应用准备内容和实际 API 交互。
- 显示实际采集到的提供商用量；区分真实 token 消耗、容量估算和未获取的用量。
- 可开启限时或持续完整记录，跨页面保持设置，并导出已结束任务。记录保存在执行端，凭据脱敏，设有保留时间和空间限额。

完整记录需要在任务开始前开启，历史上没有采集的内容无法补回。记录功能不会改变发给模型的上下文。

## 建档计划与失败恢复

- 建档统一生成章节计划，由同一套契约校验摘要、场景、人物、设定与关系；通过完整性校验后再按章节事务写入正式档案。
- 参数类型、枚举、实体 ID 或计划完整性错误会返回具体候选和字段位置，帮助模型修正；保留已接受候选及作者编辑。
- “保留候选并修正”使用当前候选继续处理。完成确认失败会明确返回错误，避免把暂存成功误报为全章建档完成。
- 修复旧候选中重复封装字段阻塞校验的问题；迁移保留候选 ID、正文和作者确认，不猜测冲突字段。
- API 与 CLI/MCP 使用共享工具契约和校验回执，Android 同步相关协议与提示词。

升级时，未完成的旧建档检查点会暂停并保留资料，可继续按当前计划契约修正。一个统一计划仍可能包含多次模型调用。

## 工具调用与存储稳定性

- 模型返回未开放的工具名称时，整批拒绝执行，并将实际可用工具及错误回执交回同一模型，最多提供两次修正机会；达到上限后保存具体原因并停止。
- 不静默替换工具名称，不执行错误批次中的部分调用；手机独立 Agent 使用相同恢复边界。
- 修复启动时重复生成数据库备份的问题，先核验数据库结构是否确需迁移，自动备份仅保留最新一份通过校验的副本。

## 优化与测试范围

本轮实际问题分析主要来自 DeepSeek API `deepseek-flash` 的运行记录。自动化回归使用隔离数据库、模拟模型和协议回放，覆盖 API、CLI/MCP 与 Android 共享契约；这不代表已经完成其他模型或 CLI 的同等实机验证。

后续将以记录中的真实请求、响应、失败率和提供商实报 token 为依据，逐步验证工具命名与描述、历史状态消息、资料组织和压缩策略的效果。`deepseek-flash` 是当前主要验证基准，不是唯一允许使用的模型。

提交前已有后端全量 2,834 项测试和 Android 330 项单元测试通过，并完成本地 Windows 安装包启动与内容校验。正式安装包由标签发布流水线构建，执行前后端、Android、安装冒烟及发布后下载校验。
